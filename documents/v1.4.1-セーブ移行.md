# v1.4.1 セーブ保存先移行

更新日：2026-09-17  
対象：Ver.1.4.1

## 変更概要

プレイ進行状況の保存先をCookieから`localStorage`へ変更する。Cookieの1項目あたりの容量制約により、所持品が増えた周回で`playingdata`の更新が拒否され、古いセーブが残る可能性があったため。

## 保存構成

| 保存先 | キー | 用途 |
| --- | --- | --- |
| `localStorage` | `the_toho:progress:v1` | 現在のプレイヤー状態とストーリー進行番号。 |
| `localStorage` | `the_toho:meta:v1` | 最高記録、図鑑、実績、ストーリー解放・既読、プレイ履歴。 |
| `localStorage` | `the_toho:run:v1` | 現在の周回ID、戦闘・逃走等の周回内情報。 |
| `localStorage` | `the_toho:settings:v1` | BGM／SE音量、アセットバージョン。 |
| Cookie | `version` | キャッシュ更新判定用。進行セーブではない。 |
| Cookie（移行元のみ） | `playingdata`・`storydata` | v1.4.0以前の進行セーブ。新規書込は行わない。 |

`the_toho:progress:v1`は次の形で保存する。

```json
{
  "schemaVersion": 1,
  "storyNum": 0,
  "player": {}
}
```

プレイヤー状態と`storyNum`を同じレコードに書き込み、片方だけが更新される状態を作らない。

## 旧Cookieからの移行

1. `the_toho:progress:v1`が存在する場合は新形式を優先する。
2. 新形式が存在せず、`playingdata` Cookieが存在する場合だけ旧形式を読み込む。
3. `storydata`が有効な非負整数なら`storyNum`へ移す。存在しない場合は0とする。
4. `localStorage`への書込に成功した後だけ`playingdata`・`storydata` Cookieを削除する。
5. 新形式が存在するが破損している場合、旧Cookieへ自動的に巻き戻さない。破損データも旧Cookieも削除せず、復元を中止する。

ゲームオーバーまたは「諦める」では`the_toho:progress:v1`だけを削除し、メタ記録・設定は維持する。旧進行Cookieが残っている場合は同時に削除する。

## 実装

- `programs/progress_storage.js`：進行セーブの読込・保存・削除、旧Cookie移行、武器攻撃力のダイスメソッド復元。
- `programs/save_safety.js`：新形式を前提とした復元前検証と削除失敗時の保護。
- `index.html`：`progress_storage.js`を`meta_progress.js`より前に読み込む。
- `tests/progress_storage.test.js`：通常保存、4KB超の保存、旧Cookie移行、復元、削除、破損データ保護を検証。

## 互換性

v1.4.0以前の有効なCookieセーブは保持し、v1.4.1初回起動時に移行する。移行失敗時は旧Cookieを削除しない。`version` CookieはHTTP／CacheStorage更新判定に引き続き使用するが、プレイ進行情報は保持しない。
