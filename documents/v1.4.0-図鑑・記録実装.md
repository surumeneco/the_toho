# v1.4.0 図鑑・最高記録・プレイ履歴 実装記録

更新日：2026-09-17  
対象ブランチ：`feature/1.4.0`  
状態：コード実装済み。今回の変更後の実ブラウザでの表示・操作検証は未実施。

## 図鑑

- タイトルの「図鑑」から直接、食料図鑑・武器図鑑・道具図鑑・素材図鑑・敵図鑑の5ボタンへ進む。中間のアイテムカテゴリ一覧は廃止。各ボタンに解放件数と率を表示し、総合解放率のみタイトル枠の下に背景なしで表示する。以前の総合・アイテム・敵の3行と背景枠は置かない。
- 各カテゴリ図鑑のタイトルはヘッダー内で従来より下に配置。「解放：n/x」の単独表示は置かない。ページ番号は「前へ」「次へ」と同じ高さ（y=1610）に配置する。未解放項目は名称・詳細を伏せる。
- アイテムは初回入手、敵は初回遭遇で解放する。食料の回復量、武器攻撃力、素材の採取道具、および敵の体力・攻撃力・出現距離は既存データから表示する。敵のドロップ候補はすべて名前と最大入手数を表示し、各行のグレー背景・白枠は付けない。候補多数の場合は表示範囲内でスクロール可能。
- ドロップ候補の各行はPhinaの `Label` を使用。Canvasに直接 `font` や `fillText` を指定する実装を廃止し、ゲームのほかの表示と同じPhina標準のフォントファミリーに統一する。既存画面に合わせたフォントサイズの指定は維持する。
- 解放ID、保存形式は変更しない。図鑑の閲覧ではプレイデータを更新しない。

## 最高記録・プレイ履歴

- タイトルの最高到達距離・最高日数は永続記録として保持し、新周回、諦める、履歴の件数制限で消さない。
- 死亡時のみ履歴を保存し、新しい順の直近10件まで残す。終了日時・距離・日数・死因・戦績・死亡時所持品を記録する。`runId` で同一死亡の履歴重複を防ぎ、履歴確定後にプレイCookieを消す。
- **変更後に保存する記録（`recordVersion: 2`）では `battleCount` は勝利回数のみを意味し、`escapeCount` に逃走回数を記録する。** 戦闘開始数 `run.battles` は戦闘結果の重複計数防止用として維持する。各戦闘の勝利・逃走結果は同じ戦闘につき一度だけ加算する。
- 旧記録の `battleCount` は勝利数ではなく戦闘開始数。内訳は復元できないため、旧履歴の画面には「旧・開始数」と表示し、逃走回数は「記録なし（旧仕様）」とする。更新途中の周回で過去の勝敗が不明な場合は、更新後に実測した結果のみ新カウンターへ加算する。
- 履歴画面のタイトルを約1行下、見出し「死亡時の記録」を約2行下へ移動。見出しに専用背景を付けず、その下に最新順の履歴ボタンを配置する。履歴一覧はページなしの縦スクロールとし、詳細から戻った時は位置を保持する。
- 詳細タイトルは「プレイ記録の詳細」。情報枠には日時・距離／日数・死因・勝利回数・逃走回数を表示。情報枠は上端を約半行下げ、下端を約1.5行上げて縮小（中心 y=570、高さ480）。死亡時の所持品は食料・武器・道具・素材の見出しと **名前・個数だけ**を表示し、性能表示はしない。
- 履歴一覧の各項目はPhinaの `Button`、死亡時所持品の各項目はPhinaの `Label` に変更。DOM要素は使用しない。文字をCanvas APIに直接描画する処理と個別のフォントファミリー指定を撤去し、Phina部品のフォントを使用する。
- スクロール領域はPhinaの `DisplayElement` の `clip` とCanvasRenderer標準のクリッピングで描画を制限する。各行は全件Phina部品として生成する通常スクロールで、仮想スクロールではない。枠外の履歴ボタンは操作不可にし、タッチのスクロール中はボタンを開かない。
- 敵による体力／気力切れ、探索・睡眠時の気力切れを区別する。「諦める」は現段階では死亡履歴へ含めない。

## 保存先と互換性

| 保存先 | キー | 内容 |
| --- | --- | --- |
| `localStorage` | `the_toho:meta:v1` | 最高記録、解放ID、直近10件の履歴。新履歴のみ `recordVersion: 2` と `escapeCount` を追加。 |
| `localStorage` | `the_toho:run:v1` | 周回ID、戦闘開始数、勝利数、逃走数、最後に結果を記録した戦闘番号、死因判定情報。 |
| `localStorage` | `the_toho:settings:v1` | BGM・SE音量とアセットバージョン。 |
| Cookie | `playingdata`、`storydata` | 旧形式と互換のプレイ進行情報。 |
| Cookie | `version` | キャッシュ判定用。 |

永続セーブの `schemaVersion: 1` は維持し、既存の履歴や図鑑登録を失わない。旧プレイCookieで確認できる現在所持品だけを図鑑へ反映し、消費済みアイテムや過去の遭遇・戦績は推測して補わない。永続記録の保存に失敗した時は、死亡画面からのプレイデータ削除を停止して再試行可能とする。諦める時の削除も保存失敗なら停止する。

アイテムと敵のIDは既存配列のカテゴリと位置から生成する。追加は各配列の末尾に限定し、順序変更・途中挿入が必要なら明示的な固定IDと旧ID対応表への移行を先に行う。

## 変更ファイル

- `programs/records_v2.js`：戦闘結果の勝利・逃走カウントと履歴形式の変更。`meta_progress.js` と `save_safety.js` の間で読み込む。
- `programs/scenes/archive_scene.js`：図鑑導線・配置・ドロップ候補・履歴表示・Phina部品によるスクロールとクリッピング、情報枠サイズ。勝利・逃走シーン拡張も定義。
- `programs/main.js`：結果を記録する勝利・逃走シーンへ登録を変更。
- `index.html`：追加記録スクリプトの読み込み順を登録。

## ブラウザ確認項目

1. 図鑑トップで総合率とカテゴリ別5ボタンを確認。各ボタンから一覧・詳細・戻るを操作し、未解放情報が見えないことを確認。
2. 各図鑑のヘッダー、一覧、ページ数と前／次ボタンの配置を確認。候補の多い敵で背景なしのドロップ一覧を末尾までスクロールし、文字のフォントが他の表示と同じことを確認。
3. 死亡履歴を10件蓄積し、見出し下のPhinaボタン一覧をスクロールして詳細へ移動・戻る。枠外のタップで遷移せず、スクロール中の誤タップや途中位置リセットがないことを確認。
4. 所持品が多い死亡履歴でカテゴリ・名前・個数を確認。上下に滑らかにスクロールしても背景枠外に文字がはみ出さず、ページ切替も性能値表示もないことを確認。
5. 履歴詳細の情報枠が「終了」から「逃走回数」までを過不足なく囲むことを確認。
6. 勝利→逃走→死亡を含む周回で勝利数・逃走数が各1回となり、敗北した戦闘は勝利数に加えない。結果画面の再生成で重複しないことも確認。
7. 更新前の履歴が旧集計と表示され、履歴・最高記録・図鑑・音量が周回／リロード後も保持されることを確認。

実績定義、ストーリー解放・再生、共通トリガー基盤は今回の実装対象外。
