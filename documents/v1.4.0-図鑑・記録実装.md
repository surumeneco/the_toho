更新日：2026-09-17  
対象ブランチ：`feature/1.4.0`  
状態：コード反映済み。今回の変更後の実ブラウザでの表示・操作検証は未実施。

## 図鑑

- タイトルの「図鑑」から直接、食料・武器・道具・素材・敵の5種類の図鑑へ進む。各ボタンにカテゴリの解放件数と解放率を表示し、図鑑トップには背景なしの総合解放率だけを別途表示する。
- 図鑑のカテゴリ別一覧は未解放の名前を伏せる。各カテゴリのページ表示は「前へ」「次へ」と同じ高さに配置する。詳細から戻った際は元のカテゴリ一覧に戻る。
- アイテムは初入手、敵は初遭遇で解放。食料の回復量・武器の攻撃力・素材の採取道具・敵の体力／攻撃力／出現距離を既存データから表示する。敵のドロップ候補は全件の名称と最大入手数を表示し、必要なら縦スクロールする。候補に個別背景・枠を付けない。
- **アイテム詳細／敵詳細の内容背景枠は上端 y=300、下端 y=1650 に統一。** 下部操作枠の上端 y=1690 との間を40px空ける。敵ドロップ候補はこの詳細枠内に収める。
- 図鑑の解放IDと永続保存形式を維持し、閲覧でプレイデータは更新しない。

## 最高記録とプレイ履歴

- 最高到達距離・最高日数は独立した永続値とし、新周回・諦める・履歴の件数制限で消さない。
- 死亡時のみ、日時・到達距離・日数・死因・戦績・死亡時の全所持品を保存し、新しい順の直近10件を維持する。履歴はページ分けせず縦スクロールし、詳細から戻ったときは一覧のスクロール位置を保持する。
- **履歴の先頭・末尾に18pxの余白を設け、Phina `Button` の15px枠線がスクロール領域の縦端で見切れないようにする。** 横方向もボタンの外枠がクリップ範囲に収まるよう左右に余白を確保する。表示範囲外の履歴ボタンは操作不能にする。
- 新規保存履歴は `recordVersion: 2`。`battleCount` は勝利回数、`escapeCount` は逃走回数。戦闘開始数 `run.battles` は結果の重複計数防止に使用し、同一戦闘の勝利／逃走は一度だけ加算する。旧履歴は開始数しかないため「旧・開始数」と明示し、逃走は「記録なし」とする。更新途中の周回で実測できなかった過去の勝敗は推測しない。
- 詳細情報には終了日時、到達距離・日数、死因、勝利回数、逃走回数を表示。所持品欄はカテゴリ見出しと名前・個数だけを表示し、性能値は出さない。
- **死亡時所持品は見出しを y=865、背景枠を y=900～1650 とし、下側を図鑑詳細と同じ位置に統一。** 枠内の y=925～1625 で通常の Phina `Label` を全件保持・縦スクロールし、`CanvasRenderer` のクリップで枠外描画を防ぐ。仮想スクロールやページ分けは使用しない。カテゴリ区切り線を従来より約40px下げ、後続の品目と重ならない行間を確保する。
- 死因は敵による体力／気力切れ、探索・睡眠時の気力切れを区別する。「諦める」は現段階では死亡履歴に含めない。

## UIの枠スタイル

既存の持ち物画面・`Text_window`・操作ボタンの役割別デザインを参照し、図鑑／履歴画面の枠線と角丸を統一する。

| 役割 | 表示と枠線 | 角丸 |
| --- | --- | --- |
| ヘッダー・下部操作枠 | 黒背景、白枠 10px | 0 |
| 詳細・所持品などの内容パネル | 濃い灰色背景、薄い灰色枠 5px | 0 |
| 通常操作・一覧・履歴ボタン | 濃い灰色背景、薄い灰色枠 15px | 0 |
| ページ操作ボタン | 濃い灰色背景、薄い灰色枠 10px | 0 |

ヘッダーは y=0～280、下部操作枠は y=1690～1920。リスト・情報・ボタンはすべてPhinaの描画部品で構成し、独自のCanvasテキストフォントやDOM部品は使用しない。

## 保存先と互換性

| 保存先 | キー | 内容 |
| --- | --- | --- |
| `localStorage` | `the_toho:meta:v1` | 最高記録・図鑑ID・直近10件の履歴。新履歴にだけ `recordVersion: 2`・`escapeCount` を追加。 |
| `localStorage` | `the_toho:run:v1` | 周回ID、戦闘開始数・勝利数・逃走数・最後の計数対象戦闘、死因判定情報。 |
| `localStorage` | `the_toho:settings:v1` | BGM／SE音量とアセットバージョン。 |
| Cookie | `playingdata`・`storydata` | 従来と互換のプレイ進行情報。 |
| Cookie | `version` | キャッシュ判定用。 |

永続データの `schemaVersion: 1` を維持し、旧履歴・図鑑の解放状態を消さない。旧Cookieから現在所持品だけを図鑑へ移行する。永続データの保存が失敗した場合、ゲームオーバー・諦める時の進行Cookie削除を停止する。アイテム／敵のIDは配列位置ベースのため、途中挿入や並べ替えの前に固定IDと移行処理が必要。

## 変更箇所

- `programs/meta_progress.js`：永続記録・所持品発見・セーブ連携。
- `programs/records_v2.js`：勝利／逃走カウントと新履歴形式。
- `programs/save_safety.js`：保存・復元時のガード。
- `programs/scenes/archive_scene.js`：図鑑・履歴画面、Phina部品によるスクロール、統一した枠の描画。
- `programs/scenes/gameover_scene.js`：死亡履歴保存成功後に進行Cookieを削除。
- `programs/main.js`・`index.html`：シーンと記録処理の読み込み。

## 実ブラウザで確認する項目

1. 食料・武器・道具・素材・敵の詳細枠の上下端がそろい、下部操作枠との間に隙間があること。
2. 履歴1件目と最終行のボタン枠線が上下左右で欠けず、スクロール中の誤タップも起きないこと。
3. 死亡時の所持品欄が上に移動し、下部操作枠の40px上で止まること。品目多数の場合も末尾までスクロールでき、枠外に文字が出ないこと。
4. 所持品の区切り線が従来より下がり、カテゴリ・品目と重ならないこと。
5. 見出し・内容枠・履歴ボタン・ページ操作ボタンが役割に応じた線幅・角丸で統一されていること。
6. 勝利・逃走の件数、旧記録表示、図鑑解放、保存・復元の動作に退行がないこと。

実績の個別定義とストーリー解放・再生・共通トリガーは今回の実装対象外。
