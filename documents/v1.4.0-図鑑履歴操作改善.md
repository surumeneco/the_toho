# v1.4.0 図鑑・履歴の削除操作と周辺UI

更新日：2026-09-17。対象：`feature/1.4.0`。

## 図鑑・プレイ履歴の削除

- 図鑑トップとプレイ履歴トップのフッターに「データ削除」を追加する。右側の「戻る」は維持する。
- 押下時は「諦める」と同様にゲーム内で背景を暗転し、「はい／いいえ」の確認を表示。確認中は背後のボタンとスクロールを停止する。
- 図鑑削除は `the_toho:meta:v1` 内の `encyclopedia.itemIds` と `encyclopedia.enemyIds` のみ空にする。履歴削除は同キー内の `history` のみ空にする。最高到達距離、最高日数、実績・ストーリー用データ、設定、進行中のプレイ情報は残す。
- `toho_save_meta()` による書き込みに失敗した場合はメモリ上の変更を元に戻し、削除せずエラーを表示する。キャンセルでは内容を変更しない。削除成功後、一覧を更新する。
- 図鑑削除後にアイテムを新たに入手・敵に遭遇すると、通常どおり再解放する。既存プレイCookieの所持品移行が実行された場合も、現在所持しているアイテムが再登録される仕様は従来どおり。

## タイトル

- 「図鑑」「プレイ履歴」の下に「実績」「ストーリー」を追加。現段階では選択SEのみで画面遷移・保存データ変更はしない。
- 4つのボタン上をタップしてもタイトルの全画面スタート処理は実行しない。音量スライダーとその他の画面タップでのゲーム開始は従来どおり。

## スクロール・死因

- 履歴一覧の先頭・末尾には元から同量の18pxの余白がある。敵のドロップ候補と履歴内所持品も描画する全行の外側に上下20pxずつ余白を確保する。制作一覧は既存の上余白20pxに合わせて下にも20pxを加える。通常の持ち物画面はヘッダー・フッターから上下20pxの余白が既にあるため変更しない。
- 死因表示は、敵に負けた場合は敵名のみ、睡眠は「寝すぎ」、制作は「作りすぎ」、探索は「歩きすぎ」とする。過去の履歴については保存済みの種別から表示だけを変換する。制作画面に入った際は周回の死亡原因判定用コンテキストに制作を記録する。
- 追加実装は `programs/archive_controls.js` で既存シーンを継承し、`index.html` の読み込み順と `programs/main.js` のシーン登録を更新する。履歴・図鑑の保存形式は変更しない。

## 実ブラウザ確認項目

1. 図鑑と履歴の削除ボタンで異なる確認文が表示され、いいえ・ダイアログ中の背景操作は何も削除しない。
2. 図鑑のみ削除しても履歴と最高記録は残る。履歴のみ削除しても図鑑・最高記録は残る。いずれも画面再読み込み後も結果が維持される。
3. 保存書込失敗時はエラーメッセージを表示し、メモリ上の履歴／解放IDも維持する。
4. タイトルの実績・ストーリーはSEのみ鳴り、ゲームが勝手に開始しない。音量操作も正常。
5. 履歴・敵ドロップ・死亡時の所持品・制作一覧を最下端までスクロールし、先頭と末尾に同等の余白がある。
6. 敵・睡眠・探索・制作の死因が指定表記となる。旧履歴の表示変更でも元の保存データが失われない。
