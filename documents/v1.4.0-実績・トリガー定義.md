## 1. 判定の共通規則

- **「累計」と明記された条件だけが全プレイ累計。それ以外は1プレイ内。** 実績解除状態はすべて永続保存し、既解除実績を別周回で再通知しない。
- 距離・生存日数・気力・数量の「達成」「以上」は所定の閾値以上。死亡／諦めるの指定日数は確定した終了時の日数と一致すること。
- 距離の内部単位はm。10km＝10000m、42.2km＝42200m、100km＝100000m、150km＝150000m、累計1000km＝1000000m、累計3927km＝3927000m。
- 「アイテムをn個以上入手」は、暫定的に**1プレイ中に実際に入手した数量の合計**を想定する。探索・制作・ドロップ等の入手元は問わず、消費しても入手数は減らさない。所持数による判定にするかは最終確認事項。
- 「敵を倒す」は当該プレイで1体以上の討伐。「累計n体」は全プレイを通じた討伐数。女の子……？の1／2／3体は同名の3個体を当該プレイ内で合算する暫定案。形態別の必須条件かどうかは未確定。
- シークレット（表中「秘」）は未解除時、名前・説明・条件を伏せる。通常（「—」）は未解除でも名前・説明を表示する。各イベントや達成通知の重複発行を禁止する。

## 13. 実装対象となる共通イベント・保存データ

| イベント・状態 | 判定に必要な情報 |
| --- | --- |
| `run_started` | 周回IDと開始状態。ロードは新規開始として扱わない。 |
| `advance_resolved` | 1回の前進、距離増分、確定距離、遭遇有無。距離累計・連続前進・連続遭遇に使用。 |
| `day_advanced` / `state_changed` | 日数・気力の確定値。生存日数・気力閾値に使用。 |
| `battle_started` | 戦闘インスタンスID・敵の固定ID。勝敗／逃走と独立した戦闘開始回数。 |
| `battle_won` / `battle_escaped` | 戦闘インスタンスID・敵ID。討伐・逃走・連続逃走と結果の二重計数防止。 |
| `damage_taken` | 単発ダメージの計算値と実減少量・攻撃ID。 |
| `item_obtained` | アイテム固定ID・正の入手数量・発生ID。 |
| `run_died` / `run_abandoned` | 終了時の日数・原因・周回ID。進行データ削除前に判定。 |

- 周回データ：各連続回数、アイテム別入手数、敵別討伐数、イベント重複防止IDなど。永続データ：累計移動m、累計生存日数、敵別累計討伐数、解除済み実績IDなど。累計は同じ移動・生存・討伐を復元・再初期化で二度足さない。
- イベントと条件評価器はストーリー解放にも共通利用し、実績表示・ストーリー再読からプレイイベントを発行しない。現在のプレイ履歴の`battleCount`は勝利回数、`escapeCount`は逃走回数。戦闘開始回数は別の統計として保持する。
- `the_toho:meta:v1`には実績ID領域、`the_toho:run:v1`には戦闘計数領域が既存。ただし**共通トリガー・全イベント／全累計・実績判定・実績一覧はまだ未実装**。保存形式の変更時には既存データを移行する。

## 14. 図鑑の同名素材統合【決定事項】

- [`datas/materials.json`](../datas/materials.json)で**名前が同じ素材は、必要道具や最大入手数の異なる複数行でも図鑑上で1種類**として扱う。例：木の葉・ツタ・木材・土・大きめの石・銅鉱石・鉄鉱石。
- 素材図鑑の件数・解放件数・解放率、アイテム図鑑全体および図鑑総合の分母／分子は同名素材を重複計上しない。どの採取方法でも当該素材を一度得れば解放する。採取データの複数行自体は保持し、必要道具ごとの情報は統合表示する。
- 現行の`material:NNNN`は配列位置ベース。**同じ名前のどの旧IDを保存済みでも、統合後の代表IDに安全に対応させる移行が必要。** 固定IDへの変更で既存図鑑を初期化しない。
- **同名統合は仕様決定のみ。図鑑表示・解放ID移行のゲーム実装は別作業。** 図鑑解放率を条件とするトリガーを作る前に反映する。
