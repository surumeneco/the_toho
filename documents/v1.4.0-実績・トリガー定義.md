[基本仕様](./v1.4.0-仕様.md)の「共通イベント・トリガー」「実績とストーリー」に対する具体的な実績定義。今後のトリガー実装では本書を参照する。名称・条件・シークレット指定はユーザー案を保持し、未決定の細部は末尾に分離する。

## 1. 共通規則

- **「累計」と書かれた条件だけが全プレイ横断の累計。その他は1プレイ中。** ただし実績の解除状態そのものは全プレイを通じて永続保持する。累計カウンターも永続保存する。
- 「達成」「生存」「以上」は指定値に到達したときの閾値判定（`>=`）。「1日目で死ぬ」「3日目で諦める」は指定日の終了イベントに対する一致判定（`===`）。
- 距離の内部単位はm。`10km=10000m`、`42.2km=42200m`、`100km=100000m`、`150km=150000m`、累計`1000km=1000000m`、累計`3927km=3927000m`。
- 指定アイテムを「n個以上入手」は、**当該プレイ中に実際に獲得した数量**の集計として扱う予定（10個条件は所持数ではなく入手累積）。制作・探索・ドロップ等、正当な入手元を横断して計上し、ロード・画面再描画による再計上を禁止する。消費や破損は入手数を減らさない。
- 「Xを倒す」は指定敵の討伐を1プレイで1回以上。「累計n体」は全プレイの討伐数。「女の子……？」の1・2・3体は、同じ表示名の敵の討伐数を1プレイ内で合算する案。フォームごとの扱いは確認事項に記録する。
- シークレットは未解除時、名前・説明・達成条件を伏せる。通常実績は未解除でも名前・説明を表示する。通知・永続解放は初回だけ。
- 以下の `ACH-001` 等は**実績固有の固定ID案**。名前の重複（`何者？`）や将来の並べ替えに左右されないよう、実装後も番号を再採番しない。表の「秘」はシークレット、`—` は通常実績。

## 13. トリガー基盤が必要とするイベント・データ

| イベントまたは状態変化 | 必要な値と用途 |
| --- | --- |
| `run_started` | 周回ID、新規周回の初期状態。ロード時の再生成は新規開始と混同しない。 |
| `advance_resolved` | 実行された前進1回、移動距離増分、最終距離、戦闘遭遇の有無。累計距離と前進・遭遇の連続回数。 |
| `day_advanced` / `state_changed` | 確定した日数・現在気力。1周回の日数と累計生存日数、気力閾値。 |
| `battle_started` | 戦闘インスタンスID、敵の固定ID。開始回数は勝利・逃走と別管理。 |
| `battle_won` / `battle_escaped` | 戦闘インスタンスID、対象敵ID。討伐・逃走・連続逃走の計数と重複防止。 |
| `damage_taken` | 一撃の計算／適用ダメージ、攻撃発生ID。10/50/100判定に使用。 |
| `item_obtained` | 固定アイテムID、今回の正の入手数、発生ID。取得元を問わず入手累計に反映。 |
| `run_died` / `run_abandoned` | 確定した終了原因、確定時の日数、周回ID。削除前に評価・永続保存。 |

- `run` カウンター：進行距離、日数、気力、前進連続数、遭遇連続数、逃走連続数、アイテムID別入手数、敵ID別討伐数、個別イベント重複防止ID。
- `lifetime` カウンター：累計進行距離、累計生存日数、敵ID別累計討伐数。死亡時だけでなく進行中にも増分保存し、復元時・リトライ時の二重加算を防ぐ。
- 実績定義とストーリー定義はイベント名・条件評価器を共用し、実績の一覧表示やストーリー再読そのものではゲームプレイイベントを発行しない。
- **戦闘回数の定義を分離する。** 戦闘開始回数（イベント基盤用）、勝利回数（現在のプレイ履歴の`battleCount`）、逃走回数（`escapeCount`）は別値。過去の旧履歴の勝敗数を推測しない。
- 現行の`the_toho:meta:v1`には実績ID保存領域、`the_toho:run:v1`には戦闘管理領域が既存だが、本書に列挙したイベント・各カウンター・判定器・実績一覧は未実装。保存形式の移行時は既存データを保持する。

## 14. 図鑑の同名素材統合【決定】

- `datas/materials.json`で**名前が同一の素材は、必要道具や最大入手数が異なる複数行でも図鑑上は同一の1種類**として扱う。例：「木の葉」「ツタ」「木材」「土」「大きめの石」「銅鉱石」「鉄鉱石」。
- 図鑑の素材一覧の表示件数・既知件数・解放率、およびアイテム総合／図鑑総合解放率の分母・分子は、同名素材を重複計数しない。どの入手経路からでも1度入手すれば、当該名称の素材1種類が解放される。必要道具ごとの採取情報は統合するが、ゲーム本体の採取データは重複行をそのまま保持する。
- 既存の`material:NNNN`はデータ配列位置由来。重複行に対して複数のIDがあり、以前の発見状態がどのIDに保存されていても、移行後の同じ素材の既知状態を失わないよう**全旧IDから新しい代表IDへの対応を用意する**。並べ替え・追加でIDがずれない固定IDへの移行は別途設計する。
- **本項は決定済み仕様で、ゲームコードの図鑑集約・移行処理は未実装。** 実績の図鑑解放率トリガーを実装する前に改修・移行・回帰確認する。

## 15. 実装前の確認事項

1. `ACH-035`の「ナイフ」は現データの「石のナイフ」を指すのか、別アイテム追加予定か。
2. 同名の敵「女の子……？」の3体は、全形態の討伐数合算でよいか、それぞれ異なる形態の討伐を求めるか。表では合算案を暫定採用した。
3. 「10連続で敵に遭遇する」のリセット契機（前進1回ごとに非遭遇ならリセットするか等）と「10連続で逃げる」のリセット契機（別行動や死亡を含むか）。
4. 一度に10/50/100ダメージは「以上」で判定すると解釈してよいか、超過ダメージを含む計算値／実際に減ったHPのどちらで判定するか。
5. 累計生存日数の開始日をいつ計上するか（各周回の初日を含むか）。日数のロード・再試行・ゲームオーバーに伴う二重計上防止方法も決める。
6. 実績の解除条件を既存プレイ／既存履歴の情報だけで事後復元するか。観測していない達成を捏造しない方針を維持する。
7. 各名前に対応するアイテム・敵の不変IDと、素材図鑑の既存位置ベースIDの安全な移行手順。
