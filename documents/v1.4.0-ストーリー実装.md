# v1.4.0 ストーリー改修・記録削除仕様

更新：2026-09-17。対象：`feature/1.4.0`。本書は従来の基本仕様・図鑑記録実装記録にある「ストーリー未実装」「履歴削除時も最高記録を保持」という旧記述を更新する。

## ストーリー定義

| 固定ID | 名称 | 解放イベント | プレイヤーに表示する条件（解放後のみ） |
| --- | --- | --- | --- |
| `story:encounter` | 遭遇 | 内部ID `enemy:girl-stage-1` の討伐 | 女の子……？を倒す |
| `story:transformation` | 変容 | 内部ID `enemy:girl-stage-2` の討伐 | 女の子……？を倒す |
| `story:premonition` | 予感 | 内部ID `enemy:girl-stage-3` の討伐 | 女の子……？を倒す |
| `story:anomaly` | 異変 | 上記3種類を**既にすべて討伐済み**の状態で、その後いずれかをもう1体討伐 | 全段階の「女の子……？」を倒した後、もう一度いずれかを倒す |

「既にすべて討伐済み」はイベント発生前の永続ストーリー解放IDで判定するため、別プレイでの討伐も対象。第3段階の初討伐と同時に第4話が解放されることはない。同名敵の表示名は統一し、固定敵IDを画面には出さない。旧 `story_num` の値だけから新解放状態を推定しない。

## 新しいストーリー・トリガーの追加手順

1. [`programs/story_definitions.js`](../programs/story_definitions.js) に、変更しない固定ID・題名・本文インデックス・解放後の条件表示文・`trigger` を追加する。`datas/story.json` に対応する本文を追加する。既存ID・本文の位置を変更せず、基本は末尾へ追加する。
2. `trigger` は `{ type: 'イベント名', all: [条件, ...] }` とし、`all`（AND）、`any`（OR）、`not` の入れ子を利用できる。用意済みの条件：敵ID、事前に解放済みのストーリーID群、解放済み実績ID、図鑑カテゴリ完成、プレイヤー距離・日数・気力・体力の閾値、イベント値の閾値、プレイ内行動回数、アイテム獲得個数、常時真。別種の条件が必要なら [`programs/story_trigger_engine.js`](../programs/story_trigger_engine.js) から `toho_register_story_condition(kind, predicate)` を登録する。
3. 既存の確定イベント（`progress`、`obtained`、`advanced`、`escaped`、`damaged`、`catalog`、`died`、`abandoned` 等）は実績イベントと共有する。勝利は `victory` イベントとして戦闘終了前に評価。**未対応の新しいイベントだけ**発生確定箇所から `toho_story_emit(type, event, returnScene)` を1度呼ぶ。イベントの名前・ペイロード・復帰先は定義と整合させる。
4. 条件が真なら解放情報・周回内挿入済みフラグ・キューを保存する。同一プレイで同一話の自動挿入は1度、別プレイでの条件再達成時は再表示する。保存失敗時に解放を確定しない。未来のイベントを追加しても既存の4話や画面側に個別の `if` を増やさない。

例：距離50kmで解放する話なら `trigger: { type: 'progress', all: [{ kind: 'playerStatAtLeast', stat: 'distance', value: 50000 }] }`。指定アイテムの合計2個獲得なら `type: 'obtained'` と `{ kind: 'itemObtained', name: 'りんご', value: 2 }` を組み合わせる。`storiesPreviouslyUnlocked` は**当該イベントが発生する前**の解放状態を参照する。

## 一覧・背景・再読

タイトルの「ストーリー」から一覧へ。実績同様、**解放済み→未解放**に並べ替え、グループ内では定義順。シークレットの区別はなく、未解放でも全話の名称を表示する。解放条件は解放済みの行だけに追加表示。未解放は文字色を薄い灰、背景色を `#353535` とし、選択不可。解放済みを押すと既存本文を再読でき、「戻る」で一覧へ戻る。再読によって条件評価・プレイ進行・実績・挿入済みフラグは変更しない。

ストーリー本文画面とタイトルからの**ストーリー一覧の両方**に `images/backgrounds/story_default.webp` を使用する。通常の履歴・図鑑画面は引き続き `history.webp` を使用。個別ストーリー背景が登録された場合のみ本文画面で優先し、読み込み失敗時は共通背景へフォールバックする。既存の本文は `datas/story.json` から変更せず読み込み、文章ロード完了までは「次へ」を操作できない。

自動挿入は確定イベント後、実際に予定されているシーンへの遷移より先に行う。解放状態・閲覧状態は `the_toho:meta:v1`、周回別の挿入済みID・待機キュー・現在話・復帰先は `the_toho:run:v1` に記録。複数同時成立は定義順にキューへ積み、完了後は元の遷移先へ復帰する。途中リロードでは保存済み現在話を復元する。勝利への復帰時に限り、ドロップに必要な敵インスタンスが復元済みかを確認する。

## ストーリーのデータ削除

ストーリー一覧の「データ削除」→確認「はい」で、ストーリーの**永続解放IDと閲覧済みID**だけを削除する。実績・図鑑・履歴・最高記録・音量・プレイデータを残し、進行中のストーリー挿入キューも変更しない。保存失敗時は元の解放・閲覧情報へ戻し、確認ダイアログを維持する。次のプレイで再度条件を満たせば解放できる。既に進行中のプレイに予約済みの話は、削除後もそのプレイのキューに従って表示され得る。

## 履歴と最高記録の削除

プレイ履歴画面の「データ削除」→確認「はい」で、履歴配列 **および** `records.bestDistanceMeters` と `records.bestDays` を同じ保存で初期化する。図鑑・実績・ストーリー・音量・現在のプレイデータは維持。保存失敗時は履歴と最高記録の両方をロールバックし、ダイアログを閉じない。図鑑・実績の削除スコープは変更しない。
