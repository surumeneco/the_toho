# THE 徒歩 v1.4.0 仕様

## 1. 対象と状態

本書は v1.4.0 で検討・実装する周回要素、共通トリガー、データ保存、制作画面の検索・攻撃力表示、シーン背景画像の仕様を記録する。**仕様記録はゲームへの機能実装を意味しない。** 未決定の細部は末尾へ分離する。

### 決定状態（2026-09-17）

- **図鑑の基本仕様：合意済み。** アイテム初回入手／敵初回遭遇で解放し、周回をまたいで保持する。素材は同じ名前の複数採取行を1種類と数える。一方、表示名「女の子……？」が同じ3体は別の敵ID・別の図鑑項目とする。詳細は [`v1.4.0-図鑑・記録実装.md`](./v1.4.0-図鑑・記録実装.md) を参照。
- **実績の個別定義と一覧画面：合意済み。** 実績83件、達成条件とシークレット指定、一覧の表示順・秘匿表示・文字色を [`v1.4.0-実績・トリガー定義.md`](./v1.4.0-実績・トリガー定義.md) に記録。トリガーと実績一覧は未実装。
- **背景カテゴリ・適用範囲・探索切替距離：合意済み。** 7つの画像対象カテゴリとリフレッシュの対象外区分を設ける。距離で変化するのは探索だけで、0／50／100kmの3種類。初期画像は計9枚。ストーリー個別背景の設定機能には対応するが、初期状態では共通画像を使用。制作一覧とサイズは [`v1.4.0-背景設計.md`](./v1.4.0-背景設計.md) に記録。
- 細部の連続条件・被ダメージの基準などは未確定。ストーリーの個別トリガーも別途定義する。

### v1.3.3実装からの変更の起点（歴史的参照）

- [`programs/global_initializer.js`](../programs/global_initializer.js)：進行状況 `storydata`・`playingdata` と設定 `BGM`・`SE`・`version` をCookieに保存し、ゲームオーバー時に進行状況のみ削除する。
- [`datas/story.json`](../datas/story.json)・[`programs/scenes/story_scene.js`](../programs/scenes/story_scene.js)：既存ストーリーは配列位置で管理し、閲覧ごとに `story_num` を進め、終了先を勝利シーンに固定する。新仕様で変更対象。
- [`programs/scenes/battle_scene.js`](../programs/scenes/battle_scene.js)：従来は特定の表示名の敵を倒した場合だけストーリーに遷移する。固定敵ID・汎用イベントへの移行対象。
- [`programs/scenes/gameover_scene.js`](../programs/scenes/gameover_scene.js)：終了時は履歴保存・実績判定をプレイデータ削除前に行う。
- [`programs/classes/text_window.js`](../programs/classes/text_window.js)：制作画面のレシピ表示の変更起点。

## 2. 保存データと寿命

| 区分 | 内容 | 保存先・寿命 |
| --- | --- | --- |
| 永続セーブ | 最高距離・最高日数、実績、ストーリーの解放と閲覧、図鑑、累計カウンター、直近10件のプレイ履歴 | `localStorage`。ゲームオーバー・再挑戦・諦める後も残す。 |
| 設定・メタデータ | BGM/SE音量、バージョン確認用の情報 | `localStorage`。ゲームオーバー後も残す。 |
| 1プレイのデータ | 体力・気力・日数・距離・所持品、プレイ内カウンター、当該プレイで挿入済みのストーリーと復帰先・未表示キュー | 当面Cookieを許容。プレイ終了時に破棄。保存先に依存しないアクセス経由で扱う。 |

設計上は `meta`（永続）、`settings`（設定）、`run`（当該プレイ）を分離し、画面側は保存先を直接操作せず読み書き用関数を介する。以下は論理モデルの例であり、3区分を単一の保存キーに格納する指示ではない。保存例のキー名は実装時の候補とする。

```json
{
  "schemaVersion": 1,
  "meta": {
    "records": { "bestDistanceMeters": 0, "bestDays": 0 },
    "achievements": { "unlockedIds": [] },
    "stories": { "unlockedIds": [], "readIds": [] },
    "encyclopedia": { "itemIds": [], "enemyIds": [] },
    "lifetimeCounters": {},
    "history": []
  },
  "settings": { "bgmVolume": 25, "seVolume": 25, "assetVersion": "1.4.0" },
  "run": {
    "counters": {},
    "firedStoryIds": [],
    "pendingStoryIds": [],
    "returnScene": null
  }
}
```

実体は永続データと設定を別キーにするなど、個別の更新・移行ができる配置とする。`schemaVersion` はゲームの `1.4.0` と独立させる。更新時に永続セーブを単純削除しない。

初回起動時は既存Cookieから有効な音量・版情報を移行し、旧形式のプレイデータは可能な範囲で復元する。移行成功確認前には旧データを消さない。従来の `story_num` は新しいストーリーIDへの対応表が必要であり、既存の進行度から確実に判定できない解放を捏造しない。Cookieの容量制約でプレイ内カウンター等を保持しきれない場合は、`run` も `localStorage` に移して同じ分離規則を守る。

保存は重複実行に耐えること。履歴確定と永続データ更新が完了してからプレイデータを消す。保存失敗時は進行・履歴を無言で破棄しない。

## 3. 共通イベント・トリガー

探索・戦闘・入手・制作・食事・睡眠・死亡等で確定したゲーム内事象をイベントとして発行し、一箇所のトリガー評価に渡す。実績とストーリーは同じイベント・条件定義を参照できる。画面遷移や表示自体を達成イベントとして誤計上しない。

| イベント／条件 | 判定に用いる情報 |
| --- | --- |
| 距離達成 | 到達距離（m）が設定閾値に達する。 |
| 日数達成 | 現在日数が設定閾値に達する。 |
| 気力達成 | 気力が設定値に到達する。閾値の方向（以上・以下・一致）は条件側で指定可能にする。 |
| 指定日数で死亡・諦める | 終了確定イベント時の日数と指定日数を照合する。 |
| 連続前進・連続遭遇・連続逃走 | 確定した個別行動ごとに連続回数を更新する。中断条件の細部は未確定。 |
| 単発被ダメージ | 1回の攻撃で受けたダメージ値。複数攻撃の合算・累積と区別する。 |
| 単発体力回復 | 1回の回復処理による体力の実増加量。 |
| 指定敵の討伐 | **表示名ではなく敵の固定ID**ごとの討伐回数。同名の3体も個別に判定する。 |
| 指定敵への敗北 | 敵IDごとの敗北回数。 |
| 指定アイテム入手 | アイテムIDごとの入手個数。「ナイフ」実績は石のナイフのID。 |
| 指定武器の喪失 | 武器IDごとの喪失個数。 |
| 図鑑解放率 | アイテム／敵／総合の対象範囲と割合を指定して判定する。同名素材は重複計上しない。 |

各カウンターには `run`（1プレイ内）と `lifetime`（全プレイ累計）を用意し、トリガー定義で集計範囲を指定する。日数・距離・気力等の状態値と、討伐・入手等の増分カウンターは別種として扱う。条件は閾値以上・以下・一致や複数条件の AND/OR に拡張可能な構造とし、存在しないイベント値を0扱いして誤解放しない。

イベント発行箇所の基準：探索の距離・気力変化確定後、睡眠の日数・体力変化確定後、攻撃の実際のダメージ確定後、敵の討伐確定後、入手・制作で所持品への加算確定後、武器の破損等による減少確定後、死亡原因確定後。**戦闘開始数・勝利数・逃走数は別々に記録する。** プレイ履歴の「戦闘回数」は勝利数のみで、逃走数を別表示する。敗北は逃走ではなく、指定の敵によりプレイが死亡終了した場合とする。個数は発生した増減量で数え、同じフレームの画面再描画・ロード復元で二重計上しない。

連続前進は「探索／前進操作を続けた回数」とし、制作・睡眠・食事等の別の任意操作で途切れる。探索から強制的に挿入された戦闘・入手・ストーリー表示そのものは、連続回数をリセットしない。被ダメージ・回復は1処理単位で判定する。最終的な境界仕様のうち未確定なものは末尾を参照。

## 4. 実績とストーリー

### 実績

**全83件。個別の固定ID・名前・解放条件・シークレット指定は [`v1.4.0-実績・トリガー定義.md`](./v1.4.0-実績・トリガー定義.md) に記録する。** 未解放の通常実績も名前と条件を見せる。未解放のシークレットは名前「？？？」、条件「隠された実績」に置き換える。解放済みは通常・シークレットを問わず本来の名前と条件を表示する。独立した説明文・詳細画面は設けない。一覧は解放済み→未解放、各グループ内は固定IDの昇順。未解放項目の文字色を若干グレーにする。

解除状態を永続セーブの `unlockedIds` に追加し、別プレイでも維持する。達成通知・保存は初回のみとし、累計カウンターは解除後も必要に応じて更新できる。解除済み実績の表示順が変わってもIDを変更しない。実績一覧の閲覧はゲームの状態・解除条件を変えない。

### ストーリー

`story_num` や配列添字ではなく、固定のストーリーIDを用いた名前付き定義に変更する。定義項目は `id`、`title`、`text`、`trigger`（必要なら表示順・優先度）を基本とする。解放済みIDと閲覧済みIDは永続保存し、タイトルの解放済みストーリー一覧から再読できるようにする。既存の4本の文章にはそれぞれIDを付与し、本文を保持する。

未解放のストーリーが条件達成した場合は解放IDを保存してシーンを挿入する。**すでに永続解放済みでも、別のプレイでそのストーリーの条件を満たした場合は再度シーンを挿入する。** 一方、同一プレイ中に同じ条件が持続・再成立しても無制限に挿入しないよう、当該プレイで挿入済みのIDを記録する。タイトルからの読み直しは解放判定・進行・実績イベント・挿入済みフラグを変更しない。

戦闘以外（距離、日数、入手、回復等）からも挿入可能にする。複数のストーリーが同時解放された場合は順序を確定させてキューに格納し、順に表示する。表示終了後はトリガー発生前に予定されていた遷移先へ復帰する。従来の「ストーリーを閉じたら必ず勝利画面」は廃止する。表示中にページを更新しても未処理キュー・復帰先・当該プレイの挿入済み判定を保持し、重複解放／遷移先喪失を起こさない。

IDは文章タイトルや表示名とは独立した不変の識別子にする。敵・アイテムにも名称変更の影響を受けないIDを割り当てる方針とし、既存の名称参照から段階的に移行する。

## 5. 図鑑【基本仕様確定】

タイトルの図鑑画面から**食料・武器・道具・素材・敵の5つへ直接**進める。アイテムは**初回入手**、敵は**初回遭遇**を解放イベントとして記録する。解放済みIDを `localStorage` の永続セーブへ保存し、周回をまたいで維持する。死亡・再挑戦・諦めるでは解除しない。初回判定は恒久的なIDを利用し、同じ項目を何度発見しても重複登録しない。

**同名素材は、異なる必要道具や採取数のデータ行を1つの図鑑項目に統合する。同名の敵「女の子……？」3体は内部IDが異なる別々の項目とする。** 3体ともプレイヤー向けの表示名は変更しない。敵IDは遭遇・討伐・ストーリー・実績の各イベントで共通して引き回す。既存図鑑IDを変更する際は旧解放状態を失わせない移行を行う。

未解放項目の名前・説明等の内容は伏せる。解放率は `解放済み対象ID数 / 対象の全ID数` に基づき、各ボタンにカテゴリ別の解放件数と率、図鑑トップに総合率を表示する。実績やストーリーの図鑑率条件も同じ解放状態を参照する。詳細情報と表示レイアウトは [`v1.4.0-図鑑・記録実装.md`](./v1.4.0-図鑑・記録実装.md) を参照。

## 6. 最高記録とプレイ履歴

最高距離（m）と最高日数は、直近履歴の件数制限とは独立した永続値として保存する。到達時の値で更新し、古い履歴の削除や新規プレイ開始で失わない。

死亡したプレイについて、**ゲームオーバー処理による削除前**に以下のスナップショットを1件確定する。

| フィールド | 内容 |
| --- | --- |
| `distanceMeters` | 最終到達距離（内部単位m。表示時にkmへ換算可）。 |
| `days` | 最終日数。 |
| `deathCause` | 死亡理由の種別と、敵が原因なら敵ID等を含む構造化情報。 |
| `battleCount` | 当該プレイの勝利回数（新履歴形式）。 |
| `escapeCount` | 当該プレイの逃走回数（新履歴形式）。 |
| `items` | 死亡時に所持していた全アイテムのカテゴリ・ID・数量の一覧。武器／食料／道具／素材等を含み、メソッドや実行時オブジェクトを保存しない。 |

履歴は新しい順の直近10件のみ残し、11件目以降は最古を削除する。履歴の追加は死亡1回につき1度だけとし、リロード・ゲームオーバー画面の再初期化で重複追加しない。死亡理由は敵による体力減少、敵による気力減少、探索・睡眠・制作による気力切れなどを区別できるようにする。表示は戦闘時は敵名のみ、探索「歩きすぎ」・睡眠「寝すぎ」・制作「作りすぎ」。履歴確定後にプレイ情報を削除し、実績・ストーリー・図鑑・最高記録・履歴・設定は消さない。旧履歴の戦闘開始回数は勝利数へ推測変換せず「旧・開始数」と区別する。

「諦める」は死亡履歴に含めないが、確定時の終了イベントは発行して実績判定する。閲覧画面の図鑑・履歴削除は確認付きでそれぞれの対象のみを削除し、最高記録等を残す。

## 7. タイトル画面

既存の開始・音量設定に加えて、最高到達距離・最高日数、および以下への入口を用意する。

- 解放済みストーリー：名称による一覧と本文の読み直し。タイトルの入口は現時点では仮ボタン。
- **実績一覧：解放済み→未解放。名前と解放条件だけを各行に表示し、詳細画面なし。未解放通常実績は実名・条件を若干グレーで表示し、未解放シークレットは「？？？」「隠された実績」を若干グレーで表示。解除済みは通常色で実名・条件を表示。** タイトルの入口は現時点では仮ボタン。
- プレイ履歴：新しい順の直近10件。各件から距離・日数・死因・勝利数・逃走数・死亡時アイテムを確認。
- 図鑑：食料／武器／道具／素材／敵に直接進むカテゴリ別閲覧画面と解放率。

これらの閲覧は進行中のプレイデータを書き換えない。

## 8. 制作画面

### 必要素材名による検索

制作画面に文字入力欄を追加し、入力文字列がレシピの**必要素材の名前**のいずれかに部分一致するものだけを表示する。制作物名や必要道具名への一致は検索条件としない。空文字では従来の一覧表示に戻す。既存の必要道具の所持条件は保持し、対象がない場合は「該当するレシピなし」を表示する。文字入力時に一覧・スクロール位置・ページ位置を破綻なく更新し、日本語入力・モバイル操作に対応する。

### 武器攻撃力の表示

制作物が武器なら、レシピウィンドウの**制作物名と「必要素材」の間**に攻撃力を1行表示する。値は武器データのダイス数・面数・固定値から導出し、例えば `4d3`、`1d10+1d3`、`1d6+1` のように表す。制作レシピに攻撃力の重複データを埋め込まない。武器以外は攻撃力行を表示せず、行数に応じてウィンドウ高さ・ボタン・スクロール範囲を再計算する。制作後の一覧更新では可能な範囲でスクロール位置を保持する。

## 9. シーン背景画像【カテゴリ・距離・初期画像数確定】

背景は各シーンにカテゴリIDを割り当て、カテゴリ共通の画像を再利用する。**距離による変更は「探索」カテゴリのみ**とし、現在距離以下で最大の開始距離を持つ背景を選択する。

| カテゴリ | 対象シーン | 初期背景 |
| --- | --- | --- |
| タイトル | タイトル | 固定画像1枚 |
| 拠点昼 | ホーム、制作、持ち物 | 固定画像1枚 |
| 拠点夜 | 睡眠 | 固定画像1枚 |
| 探索 | 探索、入手、戦闘、勝利、逃走 | 0～50km未満、50～100km未満、100km以上の3枚 |
| リザルト | ゲームオーバー | 固定画像1枚 |
| 履歴 | プレイ履歴、解放ストーリー一覧、実績、図鑑など新規閲覧シーン | 固定画像1枚 |
| その他 | ストーリー本文 | 汎用固定画像1枚。個別背景の指定機能は用意するが初期ストーリーには指定しない。 |
| 対象外 | リフレッシュ | 画像不要 |

**初期制作は計9枚。** 探索背景の開始距離は `0`、`50000`、`100000` mであり、100km以降に上限を設けない。50km・100kmにちょうど到達した場合は新背景に切り替える。探索の5シーンは同じ距離帯の画像を共有する。ストーリーに個別背景が指定された場合のみ共通背景より優先し、未設定なら「その他」を使う。ストーリー背景は距離に連動しない。

画像サイズは現行キャンバスの `SCREEN_W=1080`、`SCREEN_H=1920` に揃え、**1080×1920px／縦長9:16を推奨**する。ファイル形式は容量を考慮してWebPを推奨し、画像はUI・文字・ボタンを描き込まない背景単体とする。画像・設定が見つからない場合はカテゴリのデフォルト、それもなければ従来の背景色へフォールバックする。画面最背面に配置してボタン操作を妨げず、GitHub Pagesのサブパスとバージョン付きアセットURLを考慮して読み込む。実際の画像・絵柄および描画時の拡大・切り抜き方法は未決定。

現行のシーン登録は [`programs/main.js`](../programs/main.js) に定義する。`loading_scene.js` はファイルとして存在するが未登録であり、現時点では画像制作対象外。解放ストーリー一覧は「履歴」に、そこから再生するストーリー本文は「その他」に属する。

**9枚の個別用途・推奨ファイル名とパス・既存の距離仕様の調査結果は [`v1.4.0-背景設計.md`](./v1.4.0-背景設計.md) を参照。**

## 10. 実装の接続順と確認観点

1. 保存形式と永続／プレイ／設定の責務を分離し、旧Cookieの移行を確保する。
2. ゲーム内の確定イベントと `run`／`lifetime` のカウンターを一元化する。敵の固定IDは同名の3体でも別々に維持する。
3. 同じトリガー評価器から実績解放・ストーリー解放を処理し、ストーリー挿入キューとシーン復帰を実装する。
4. 図鑑では同名素材を統合し、既存の図鑑解放IDを移行する。最高記録、死亡時スナップショット、履歴10件制限を維持する。
5. タイトルの実績・ストーリー仮ボタンをそれぞれの閲覧画面につなぎ、一覧の秘匿・文字色・ソートと既存背景を確認する。

最低限の確認事項：同一イベントの二重計上防止、実績の周回間保持、同名の敵を別IDで討伐判定、未解放シークレットの秘匿と解放済み優先ソート、解放済みストーリーの別プレイ再挿入／同プレイ重複抑制、戦闘以外からの挿入と元の遷移先への復帰、死亡時の所持品・原因を削除前に記録、履歴が常に直近10件で最高記録と独立、旧セーブと音量の移行、検索・武器攻撃力、背景選択の優先順位とフォールバック。
