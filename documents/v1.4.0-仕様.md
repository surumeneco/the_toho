# THE 徒歩 v1.4.0 仕様

## 1. 対象と状態

本書は v1.4.0 で検討・実装する周回要素、共通トリガー、データ保存、制作画面の検索・攻撃力表示、シーン背景画像の仕様を記録する。**仕様記録はゲームへの機能実装を意味しない。** 未決定の細部は末尾へ分離する。

### 決定状態（2026-09-16）

- **図鑑の基本仕様：合意済み。** アイテム初回入手／敵初回遭遇で解放し、周回をまたいで保持する。未解放内容は伏せ、アイテム／敵／総合の解放率を扱えるようにする。詳細情報の開示範囲は未決定。
- **背景画像の選択規則：合意済み。** 原則「シーンカテゴリ × 到達距離」で選択し、ストーリーに限って個別背景による上書きを許す。シーンの具体的なカテゴリ割り当て、切替距離、画像は未決定。
- 個々の実績、細部のイベント条件などは本書の基盤仕様から別途定義する。

### v1.3.3 実装からの変更点

- [`programs/global_initializer.js`](../programs/global_initializer.js)：進行状況 `storydata`・`playingdata` と設定 `BGM`・`SE`・`version` をCookieに保存し、ゲームオーバー時に進行状況のみ削除する。
- [`datas/story.json`](../datas/story.json)：ストーリーを配列の位置で管理。[`programs/scenes/story_scene.js`](../programs/scenes/story_scene.js)：表示のたびに `story_num` を進め、終了先を勝利シーンに固定。
- [`programs/scenes/battle_scene.js`](../programs/scenes/battle_scene.js)：特定名の敵を倒した場合だけストーリーシーンへ遷移する。汎用イベント通知・実績・戦績集計は未実装。
- [`programs/scenes/gameover_scene.js`](../programs/scenes/gameover_scene.js)：画面初期化時に進行状況を削除する。履歴・死亡時の所持品を記録する処理はその削除より前に行う必要がある。
- [`programs/classes/text_window.js`](../programs/classes/text_window.js)：レシピ表示に制作物と必要素材があるが、武器攻撃力表示はない。

## 2. 保存データと寿命

| 区分 | 内容 | 保存先・寿命 |
| --- | --- | --- |
| 永続セーブ | 最高距離・最高日数、実績、ストーリーの解放と閲覧、図鑑、累計カウンター、直近10件のプレイ履歴 | `localStorage`。ゲームオーバー・再挑戦・諦める後も残す。 |
| 設定・メタデータ | BGM/SE音量、バージョン確認用の情報 | `localStorage`。ゲームオーバー後も残す。 |
| 1プレイのデータ | 体力・気力・日数・距離・所持品、プレイ内カウンター、当該プレイで挿入済みのストーリーと復帰先・未表示キュー | 当面Cookieを許容。プレイ終了時に破棄。保存先に依存しないアクセス経由で扱う。 |

設計上は `meta`（永続）、`settings`（設定）、`run`（当該プレイ）を分離し、画面側は保存先を直接操作せず読み書き用関数を介する。以下は論理モデルの例であり、3区分を単一の保存キーに格納する指示ではない。保存例のキー名は実装時の候補とする。

```json
{
  "schemaVersion": 1,
  "meta": {
    "records": { "bestDistanceMeters": 0, "bestDays": 0 },
    "achievements": { "unlockedIds": [] },
    "stories": { "unlockedIds": [], "readIds": [] },
    "encyclopedia": { "itemIds": [], "enemyIds": [] },
    "lifetimeCounters": {},
    "history": []
  },
  "settings": { "bgmVolume": 25, "seVolume": 25, "assetVersion": "1.4.0" },
  "run": {
    "counters": {},
    "firedStoryIds": [],
    "pendingStoryIds": [],
    "returnScene": null
  }
}
```

実体は永続データと設定を別キーにするなど、個別の更新・移行ができる配置とする。`schemaVersion` は保存形式の版であり、ゲームの `1.4.0` と独立させる。更新時に永続セーブを単純削除しない。

初回起動時は既存Cookieから有効な音量・版情報を移行し、旧形式のプレイデータは可能な範囲で復元する。移行成功確認前には旧データを消さない。従来の `story_num` は新しいストーリーIDへの対応表が必要であり、既存の進行度から確実に判定できない解放を捏造しない。Cookieの容量制約でプレイ内カウンター等を保持しきれない場合は、`run` も `localStorage` に移して同じ分離規則を守る。

保存は重複実行に耐えること。履歴確定と永続データ更新が完了してからプレイデータを消す。保存失敗時は進行・履歴を無言で破棄しない。

## 3. 共通イベント・トリガー

探索・戦闘・入手・制作・食事・睡眠・死亡等で確定したゲーム内事象をイベントとして発行し、一箇所のトリガー評価に渡す。実績とストーリーは同じイベント・条件定義を参照できる。画面遷移や表示自体を達成イベントとして誤計上しない。

| イベント／条件 | 判定に用いる情報 |
| --- | --- |
| 距離達成 | 到達距離（m）が設定閾値に達する。 |
| 日数達成 | 現在日数が設定閾値に達する。 |
| 気力達成 | 気力が設定値に到達する。閾値の方向（以上・以下・一致）は条件側で指定可能にする。 |
| 指定日数で死亡 | 死亡確定イベント時の日数と指定日数を照合する。 |
| 連続前進 | 連続した探索／前進操作の回数。 |
| 単発被ダメージ | 1回の攻撃で受けたダメージ値。複数攻撃の合算・累積と区別する。 |
| 単発体力回復 | 1回の回復処理による体力の実増加量。 |
| 指定敵の討伐 | 敵IDごとの討伐回数。 |
| 指定敵への敗北 | 敵IDごとの敗北回数。 |
| 指定アイテム入手 | アイテムIDごとの入手個数。 |
| 指定武器の喪失 | 武器IDごとの喪失個数。 |
| 図鑑解放率 | アイテム／敵／総合の対象範囲と割合を指定して判定する。 |

各カウンターには `run`（1プレイ内）と `lifetime`（全プレイ累計）を用意し、トリガー定義で集計範囲を指定する。日数・距離・気力等の状態値と、討伐・入手等の増分カウンターは別種として扱う。条件は閾値以上・以下・一致や複数条件の AND/OR に拡張可能な構造とし、存在しないイベント値を0扱いして誤解放しない。

イベント発行箇所の基準：探索の距離・気力変化確定後、睡眠の日数・体力変化確定後、攻撃の実際のダメージ確定後、敵の討伐確定後、入手・制作で所持品への加算確定後、武器の破損等による減少確定後、死亡原因確定後。総戦闘回数は戦闘開始1回につき1加算し、逃走も開始済みの戦闘として数える。敗北は逃走ではなく、指定の敵によりプレイが死亡終了した場合とする。個数は発生した増減量で数え、同じフレームの画面再描画・ロード復元で二重計上しない。

連続前進は「探索／前進操作を続けた回数」とし、制作・睡眠・食事等の別の任意操作で途切れる。探索から強制的に挿入された戦闘・入手・ストーリー表示そのものは、連続回数をリセットしない。被ダメージ・回復は1処理単位で判定する。最終的な境界仕様のうち未確定なものは末尾を参照。

## 4. 実績とストーリー

### 実績

実績は順序に依存しない固定ID、実績名、短い説明文、公開種別（通常／シークレット）、トリガー条件で定義する。通常実績は未解放でも名称・説明を表示し、シークレットは解放まで名称・説明・条件を伏せる。達成を永続セーブの `unlockedIds` に追加し、別プレイでも解除状態を維持する。達成通知・保存は初回のみとし、累計カウンターは解除後も必要に応じて更新できる。

### ストーリー

`story_num` や配列添字ではなく、固定のストーリーIDを用いた名前付き定義に変更する。定義項目は `id`、`title`、`text`、`trigger`（必要なら表示順・優先度）を基本とする。解放済みIDと閲覧済みIDは永続保存し、タイトルの解放済みストーリー一覧から再読できるようにする。既存の4本の文章にはそれぞれIDを付与し、本文を保持する。

未解放のストーリーが条件達成した場合は解放IDを保存してシーンを挿入する。**すでに永続解放済みでも、別のプレイでそのストーリーの条件を満たした場合は再度シーンを挿入する。** 一方、同一プレイ中に同じ条件が持続・再成立しても無制限に挿入しないよう、当該プレイで挿入済みのIDを記録する。タイトルからの読み直しは解放判定・進行・実績イベント・挿入済みフラグを変更しない。

戦闘以外（距離、日数、入手、回復等）からも挿入可能にする。複数のストーリーが同時解放された場合は順序を確定させてキューに格納し、順に表示する。表示終了後はトリガー発生前に予定されていた遷移先へ復帰する。従来の「ストーリーを閉じたら必ず勝利画面」は廃止する。表示中にページを更新しても未処理キュー・復帰先・当該プレイの挿入済み判定を保持し、重複解放／遷移先喪失を起こさない。

IDは文章タイトルや表示名とは独立した不変の識別子にする。敵・アイテムにも名称変更の影響を受けないIDを割り当てる方針とし、既存の名称参照から段階的に移行する。

## 5. 図鑑【基本仕様確定】

タイトルから「図鑑 → アイテム／敵」を開けるようにする。アイテムは**初回入手**、敵は**初回遭遇**を解放イベントとして記録する。解放済みIDを `localStorage` の永続セーブへ保存し、周回をまたいで維持する。死亡・再挑戦・諦めるでは解除しない。初回判定は恒久的なIDを利用し、同じ項目を何度発見しても重複登録しない。

未解放項目の名前・説明等の内容は伏せる。図鑑解放率は `解放済み対象ID数 / 対象の全ID数` に基づき、アイテム／敵／総合の対象範囲をトリガー側で指定可能にする。総合率は両カテゴリの対象件数を合わせた比率とする。実績やストーリーの図鑑率条件は、この永続解放状態を参照する。

解放後の個別詳細に能力値・敵ドロップ情報などをどこまで掲載するかは未確定。ここで確定したのは解放条件、永続性、未解放時の秘匿、閲覧入口、カテゴリ別・総合の解放率である。

## 6. 最高記録とプレイ履歴

最高距離（m）と最高日数は、直近履歴の件数制限とは独立した永続値として保存する。到達時の値で更新し、古い履歴の削除や新規プレイ開始で失わない。

死亡したプレイについて、**ゲームオーバー処理による削除前**に以下のスナップショットを1件確定する。

| フィールド | 内容 |
| --- | --- |
| `distanceMeters` | 最終到達距離（内部単位m。表示時にkmへ換算可）。 |
| `days` | 最終日数。 |
| `deathCause` | 死亡理由の種別と、敵が原因なら敵ID等を含む構造化情報。 |
| `battleCount` | 当該プレイで開始した戦闘総数。 |
| `items` | 死亡時に所持していた全アイテムのカテゴリ・ID・数量の一覧。武器／食料／道具／素材等を含み、メソッドや実行時オブジェクトを保存しない。 |

履歴は新しい順の直近10件のみ残し、11件目以降は最古を削除する。履歴の追加は死亡1回につき1度だけとし、リロード・ゲームオーバー画面の再初期化で重複追加しない。死亡理由は敵による体力減少、敵による気力減少、探索・睡眠等による気力切れなどを区別できるようにする。履歴確定後にプレイ情報を削除し、実績・ストーリー・図鑑・最高記録・履歴・設定は消さない。

「諦める」を履歴に含めるかは未確定。現段階では死亡履歴と混同せず、通常の死亡処理とは別の終了理由として扱う。

## 7. タイトル画面

既存の開始・音量設定に加えて、最高到達距離・最高日数、および以下への入口を用意する。

- 解放済みストーリー：名称による一覧と本文の読み直し。
- 実績一覧：通常実績は未解除でも名称・説明を表示。シークレットは解除まで伏せる。解除済み状態を表示。
- プレイ履歴：新しい順の直近10件。各件から距離・日数・死因・戦闘総数・死亡時アイテムを確認。
- 図鑑：アイテム／敵に分けた閲覧画面と解放率。

これらの閲覧は進行中のプレイデータを書き換えない。

## 8. 制作画面

### 必要素材名による検索

制作画面に文字入力欄を追加し、入力文字列がレシピの**必要素材の名前**のいずれかに部分一致するものだけを表示する。制作物名や必要道具名への一致は検索条件としない。空文字では従来の一覧表示に戻す。既存の必要道具の所持条件は保持し、対象がない場合は「該当するレシピなし」を表示する。文字入力時に一覧・スクロール位置・ページ位置を破綻なく更新し、日本語入力・モバイル操作に対応する。

### 武器攻撃力の表示

制作物が武器なら、レシピウィンドウの**制作物名と「必要素材」の間**に攻撃力を1行表示する。値は武器データのダイス数・面数・固定値から導出し、例えば `4d3`、`1d10+1d3`、`1d6+1` のように表す。制作レシピに攻撃力の重複データを埋め込まない。武器以外は攻撃力行を表示せず、行数に応じてウィンドウ高さ・ボタン・スクロール範囲を再計算する。

## 9. シーン背景画像【選択規則確定・割り当て未決定】

### 背景決定の基本規則

原則、**「シーンカテゴリ × 現在の到達距離」**に対応する背景画像を選択する。各シーンには画像パスを直接重複設定するのではなく、カテゴリIDを割り当てる。カテゴリごとに距離別画像とカテゴリ共通のデフォルト画像を保持できる。例外として、**ストーリーだけはストーリーIDごとに専用背景画像を任意設定できる。** 戦闘の敵別背景など、他の個別上書き規則は今回の決定対象に含めない。

優先順位：

1. ストーリー表示中、該当するストーリーIDに専用背景が明示されていれば、その画像を使用する。
2. それ以外は現在のシーンカテゴリと到達距離から該当する背景を選択する。距離帯は開始距離（m）を閾値とし、**現在距離以下で最大の開始距離**を持つ設定を採用する。
3. 距離別設定に該当する画像がなければ、カテゴリ共通のデフォルト背景へフォールバックする。
4. 設定・アセットが存在しない、または読み込みに失敗したときは従来の背景色へフォールバックする。

ストーリー専用画像が未指定の場合は2以降の共通規則を使用する。到達距離を持たない画面（タイトルや将来の図鑑等）について距離をどう扱うかは、カテゴリの割り当てと同時に決める。最高記録を勝手に現在距離として使用しない。背景はUI・文章・ボタンより背面に描画し、クリック判定を妨げない。画像表示範囲・縦横比・画面解像度への対応を共通処理にまとめ、GitHub Pagesのサブパスとバージョン付きアセットURLに対応する。具体的な画像、切り抜き方式、切替距離は未決定。

### 現行シーン棚卸し（コード確認済み）

[`programs/main.js`](../programs/main.js) に登録済みの13シーンは次のとおり。これは**現行の機能分類**であり、背景カテゴリへの最終割り当てではない。

| 機能上の区分 | 現在のシーン | 現状の役割 |
| --- | --- | --- |
| 開始・メニュー | `タイトル` | ゲーム開始と音量設定。v1.4で各種閲覧画面の入口を追加予定。 |
| プレイ拠点・操作 | `ホーム`、`制作`、`持ち物`、`睡眠` | 状態確認・行動選択、制作、所持品の確認／飲食、睡眠による回復と日数進行。 |
| 探索・成果 | `探索`、`入手` | 探索時の距離／気力更新と分岐、探索でのアイテム入手。 |
| 戦闘・戦闘結果 | `戦闘`、`勝利`、`逃走` | 対敵戦闘、討伐後のアイテム取得、逃走結果。 |
| 物語 | `ストーリー` | ストーリー本文の表示。v1.4で個別背景を任意設定可能にする。 |
| 終了 | `ゲームオーバー` | 死亡結果と再挑戦などの操作。 |
| 内部遷移 | `リフレッシュ` | 「ロード中」を表示して指定シーンへ直ちに遷移する中継画面。 |

加えて [`programs/scenes/loading_scene.js`](../programs/scenes/loading_scene.js) はファイルとして存在するが、`programs/main.js` の登録一覧にはない。登録済み13シーンとは区別する。これから追加する図鑑・実績・履歴・ストーリー一覧等の閲覧画面は、現状の13シーンには含まれない。

### 背景カテゴリ割り当ての検討観点（まだ未決定）

同じ画像を共有する単位は「機能」ではなく「描きたい場所・雰囲気」を基準に検討する。例えば、制作と持ち物をホームと共有するか、探索・入手・勝利・逃走を同じ野外背景にするか、戦闘のみ独立させるかを決める。タイトル／終了／図鑑などプレイ中の距離を持たない画面は専用カテゴリや固定背景を検討する。`リフレッシュ` のような中継画面に背景画像が必要かも未決定。現段階ではカテゴリ名・個数・各シーンの所属を確定しない。

## 10. 実装の接続順と確認観点

1. 保存形式と永続／プレイ／設定の責務を分離し、旧Cookieの移行を確保する。
2. ゲーム内の確定イベントと `run`／`lifetime` のカウンターを一元化する。
3. 同じトリガー評価器から実績解放・ストーリー解放を処理し、ストーリー挿入キューとシーン復帰を実装する。
4. 図鑑、最高記録、死亡時スナップショット、履歴10件制限を接続してからゲームオーバー削除を行う。
5. タイトル閲覧画面、制作画面検索・武器攻撃力、共通背景設定を実装する。

最低限の確認事項：同一イベントの二重計上防止、実績の周回間保持、解放済みストーリーの別プレイ再挿入／同プレイ重複抑制、戦闘以外からの挿入と元の遷移先への復帰、死亡時の所持品・原因を削除前に記録、履歴が常に直近10件で最高記録と独立、旧セーブと音量の移行、空・一致・不一致検索、武器だけの攻撃力行、背景選択の優先順位とフォールバック。
